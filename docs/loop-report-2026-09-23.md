## 1. 진단 — 0건의 원인은 하나가 아니었다

측정부터 했다. 추측으로 손대면 어느 게이트가 범인인지 영영 모른다.

### 1-1. 게시 이력 (`data/bot.db`, 기사 109건)

```
마지막 게시: 2026-06-14
이후 100일간 게시 0건
pending(저수지) 0건  ← 심사 통과분이 목표 수량을 단 한 번도 넘긴 적이 없다
```

`pending = 0`이 핵심 신호다. 저수지가 비어 있다는 건 **수율에 여유가 전혀 없었다**는 뜻이고,
어느 게이트든 한 번 흔들리면 그날은 0건이 된다는 뜻이다.

### 1-2. 깔때기 실측 (라이브 API)

기존 코드로 실제 파이프라인을 돌려 단계별로 쟀다.

| 실행 | 검색 | 중복제거 후 | 본문검증 | 편집심사 | 게시 |
|------|------|------------|---------|---------|------|
| 1일차 (빈 DB) | 8 | 7 | 6 | 5 | 2 |
| 2일차 (같은 DB) | 8 | 5 | 3 | **1** | 2* |

\* 2일차의 2건은 1일차 저수지 잔여분. 자체 수율로는 1건.

`OVERFETCH_MIN = 8`은 목표 2건에 대해 **구조적으로 부족했다**.
종단 수율이 약 12~25%이므로 기대 게시량이 1.0~2.0건 — 즉 **설계상 절반은 목표 미달**이다.

### 1-3. 치명적 버그 — URL 정규화로 인한 무한 리다이렉트

`canonicalize_url()`은 후행 슬래시를 떼는데, `fetch_html()`이 **리다이렉트 홉마다 다시 정규화**했다.

```
GET /2025/Jun/2/claude-trace   → 301 Location: /2025/Jun/2/claude-trace/
   canonicalize → /2025/Jun/2/claude-trace   (슬래시가 또 떨어짐)
GET /2025/Jun/2/claude-trace   → 301 ... 무한 반복 → 4홉 소진 → fetch 실패
```

실측으로 확인했다. Django·WordPress·Ghost처럼 **슬래시 경로를 정본으로 쓰는 사이트가 전부 fetch 실패**했고,
여기에 simonwillison.net 같은 최고 품질 실무자 블로그가 포함된다.
`web_search`가 잘 찾아와도 검증 단계에서 조용히 사라졌다.

### 1-4. 관측 불가 — 실패 사유가 기록되지 않았다

`fetch_html()`은 실패 시 `None`만 돌려줬다. 차단(403)인지, 타임아웃인지, 리다이렉트 루프인지
구분할 수 없으니 **어느 게이트를 완화해야 하는지 판단할 근거가 없었다**.

### 1-5. 서킷 브레이커 부재 (루프 도중 실제로 터짐)

루프 2일차에 Anthropic 크레딧이 소진됐다. 그러자 파이프라인은

```
완화 패스 3회 × 톱업 2라운드 × 필라 3개 + 폴백 = 실행당 18회 이상
```

을 **전부 같은 실패로 낭비**하고, 사용자에게는 "게시 대상 0개"만 남겼다.
진짜 원인은 로그 깊숙이 묻혔다. 이 실패 모드가 방치되면 **매일 조용히 0건**이 반복된다 —
관측된 100일 블랙아웃과 정확히 같은 모습이다.

### 1-6. 신선도 7일 컷이 과도

모델이 스스로 남긴 후보 평가 로그에서, 나열한 13개 중 **7개를 "7일 초과"로 자체 폐기**했다.
버려진 것 중에는 실무자가 쓴 심층 가이드가 다수였다. 실무 아티클의 유통 주기는 2~4주다.

## 2. 변경 사항

### 2-1. 3개 필라로 분리 — 커버리지와 정책의 단위

기존엔 토픽 8개를 **한 번의 검색 호출**에 몰아넣었다. 그 결과 모델은 가장 검색하기 쉬운
주제로 몰렸다(실측: 반환 8건 중 5건이 Claude Code 계열). 주제군마다 호출을 쪼갰다.

| 필라 | 내용 | 신선도 | 배분 |
|------|------|--------|------|
| `ai_practice` | 에이전틱 코딩, 컨텍스트 엔지니어링, 평가 하네스 + **구독할 피드·뉴스레터·스레드** | 14일 | 5 |
| `ai_game` | AI로 에셋·UI·사운드 제작 + **AI로 만든 게임 데브로그·포스트모템** | 45일 | 3 |
| `graphics_3d` | **무료·오픈소스 AI 3D 생성**, 무료 티어 비교, 그래픽스 기초 | 120일 | 2 |

필라 3개를 **동시 호출**하므로 벽시계 시간은 늘지 않는다.
정의의 단일 출처는 `.claude/agents/news-curation-agent.md` 프론트매터다.

신규 토픽: `agentic_coding_workflow`, `context_engineering`, `ai_dev_feeds`,
`ai_made_games`, `free_ai_3d_tools`, `graphics_fundamentals`, `asset_pipeline`.

신규 분류(`content_type`): `dev_feed`, `ai_made_game`, `graphics_3d_resource`.
기존 2종만 허용하던 코드가 "구독할 피드"나 "무료 3D 도구 비교"를 분류 부적합으로 전량 탈락시켰다.

### 2-2. 0건 방지 — 점진 완화 루프

목표에 미달하면 신선도 창과 품질컷을 한 단계씩 넓혀 재검색한다.

```
패스 1: 창 14일 · 품질컷 62/70
패스 2: 창 30일 · 품질컷 58/64
패스 3: 창 90일 · 품질컷 55/60
→ 그래도 미달이면 HN·RSS 후보풀
```

**사용자 의도는 넘지 않는다.** 활성 `curation_intent`가 "최근 24시간"을 지정했다면
0건이 되더라도 창을 넓히지 않고 품질컷만 내린다 — 명시적 지시를 어기는 건 0건보다 나쁘다.

### 2-3. 저수지 우선 조회

검색 전에 전날 잉여(pending)부터 본다. 채워지면 **API 호출 0회, 비용 $0**으로 브리핑이 나간다.
오버페치 상향으로 저수지가 실제로 쌓이기 시작하면서 이 경로가 살아났다.

### 2-4. 수집량 재조정 (실측 기반)

| 상수 | 이전 | 이후 | 근거 |
|------|------|------|------|
| `ARTICLES_PER_POST` | 2 | 6 | 학습용 피드는 폭이 생명 |
| `RECENCY_MAX_AGE_DAYS` | 7 | 14 | 모델이 후보 13개 중 7개를 7일 컷으로 자체 폐기 |
| `OVERFETCH_MIN` | 8 | 12 | 종단 수율 역산 |
| `OVERFETCH_MAX` | 24 | 36 | |
| `WEB_SEARCH_MAX_USES` | 6 | 8 | 필라당 예산 (토픽 4~6개 커버) |
| `CANDIDATES_PER_PUBLISHED` | — | 2.5 | 이 배수를 넘기면 톱업 생략 → **$1 절감** |

### 2-5. 리다이렉트 버그 수정

`canonicalize_url()`(저장 키)과 `request_url()`(요청 URL)을 분리했다.
요청 경로는 슬래시를 **그대로 유지**하고, `seen` 집합으로 순환도 끊는다.

검증:
```
수정 전: simonwillison.net/2025/Jun/2/claude-trace/ → DROP[fetch_failed]
수정 후: → 본문 4,453자 수신, URL 경로에서 2025-06-02 파싱 → 정당하게 STALE 판정
```

### 2-6. 관측 가능성 — 사유별 계측

`fetch_page()`가 실패 사유를 반환한다:
`http_403` / `http_404` / `timeout` / `redirect_loop` / `not_html` / `dns_failed` / `connection_error`,
그리고 검증 게이트 `body_too_short` / `language_rejected` / `stale`.

라이브 실행에서 바로 쓸모가 나왔다:
```
본문검증 9/18 — stale 4, body_too_short 2, timeout 1, http_500 1, http_403 1
```
이제 "본문 검증 실패"가 아니라 **무엇을 고쳐야 하는지**가 보인다. Discord 메시지에도 노출된다.

### 2-7. 서킷 브레이커

크레딧 소진·인증 실패는 `claude_search.FatalSearchError`로 즉시 전파해 남은 패스를 중단한다.
Discord에는 조치 방법까지 적어 알린다.

실전 검증 (실제로 차단된 API 상대):
```
수정 전: 18회 이상 낭비 → "게시 대상 0개" (원인 불명)
수정 후: 3회 호출 후 즉시 중단
  🛑 Anthropic API 계정 문제로 큐레이션을 중단했습니다.
  → 크레딧 잔액 또는 ANTHROPIC_API_KEY를 확인하세요. 해결 전까지 매일 0건이 반복됩니다.
```

### 2-8. 병렬화와 배치 심사

- 본문 검증: 순차 → **8-way 병렬** (read timeout 30s → 15s)
- 편집 심사: 후보 전체 1회 호출 → **8건 배치 병렬**.
  한 배치가 `max_tokens`에 잘려도 나머지는 살아남는다. 기존엔 잘리면 **그날 전체가 0건**이었다.

### 2-9. 다양성 제약

브리핑 1회당 같은 소스 2건, 같은 주제 2건까지.

주제 중복은 제목 Jaccard(0.55)로 안 잡혔다 — 실측에서 "GPT-6 Astra" 관련 서로 다른 블로그 글
3건이 6건 중 절반을 차지했는데 Jaccard가 0.19였다. 고유명사는 붙어 다니므로
**공유 바이그램 + 토큰 겹침 3개 이상**을 같은 주제로 판정하도록 바꿨다.

### 2-10. 2차 경로(HN·RSS) 개편

뉴스 매체 위주였던 RSS를 **실무자 1차 소스** 중심으로 교체했다.
Simon Willison, eugeneyan, Hamel Husain, Lilian Weng, GitHub Engineering, Hugging Face,
Martin Fowler, InfoQ AI, NVIDIA Developer, Godot, Blender Developers 등.

편집 심사가 어차피 뉴스성 기사를 떨어뜨리므로, 뉴스 피드만 넣어두면 보충이 항상 실패한다.

검증 (API 비용 0):
```
HackerNews 19개 + RSS 102개 → 적격 63개 → 30개 채택
```

## 5. 오프라인 시뮬레이션 — 연속 운영 0건 발생률

라이브 연속 실행이 막혔으므로, **외부 경계 3곳만 대체하고 파이프라인은 진짜로 돌리는**
시뮬레이터를 만들었다 (`tools/sim_world.py`).

```
대체한 것 (3곳)              진짜로 도는 것
──────────────────────────  ────────────────────────────────────────────
claude_search.search_articles   필라 팬아웃 · 쿼터 배분 · 톱업 트리거
HTTP 전송 계층 (httpx)          request_url · 리다이렉트 추적 · 본문/언어/발행일 검증
editorial_review._request_review 완화 루프 · 저수지 · 근중복/주제중복 · 랭킹 · 다양성 · DB 제약
```

`fetch_page`를 통째로 스텁하지 **않은** 것이 핵심이다. 그렇게 하면 이번에 고친
URL 정규화 코드가 경로에서 빠져 정작 검증해야 할 버그를 못 잡는다.
전송 계층만 가짜로 두니 리다이렉트 손실이 통과율에 그대로 드러났다.

수율은 라이브 실측값에 맞췄다 (fetch 실패 15%, 본문 부족 10%, 발행일 미상 30%,
창 밖 후보 25%, 품질 N(76,10)). 결과 본문검증 통과율 52% — 라이브 50%와 일치한다.

### 5-1. 기본 공급(필라당 8/4/2건/일), 목표 6건, 7일

```
 DAY  게시  수집   본문검증   심사   패스  검색
   1    6    29     17/29    15/17    1     3
   2    6     0       0/0      0/0    0     0   ← 저수지만으로 처리 (비용 $0)
   3    6    14     10/14     9/10    1     3
   4    6     0       0/0      0/0    0     0   ← 저수지
   5    6    29     17/29    13/17    1     3
   6    6     0       0/0      0/0    0     0   ← 저수지
   7    6    24     14/24    10/13    1     3

0건 발생 0/7일 · 목표미달 0/7일 · 평균 게시 6.0건
```

오버페치를 올리자 **저수지가 실제로 쌓여** 이틀에 한 번은 검색 없이 브리핑이 나간다.
이게 비용이 $2.19 → $1.14로 떨어진 실제 메커니즘이다.

### 5-2. 공급량 스윕 — 어디까지 버티는가

같은 세계·같은 시드에서 변경 전(LEGACY) 구성과 짝지어 비교했다.
LEGACY는 git 이전 리비전의 실제 값이며 **리다이렉트 버그도 재현**했다
(`request_url` → `canonicalize_url`).

## 7. 남은 리스크

1. **본문검증 통과율 50%** (라이브 9/18). 최대 손실 구간이다. `stale`이 절반이므로 필라별 창을
   더 넓히거나, 검색 단계에서 날짜 판별 정확도를 올리는 쪽이 남아 있다.
2. **모델이 URL을 지어내는 경우가 있다.** 프롬프트에 금지 문구를 넣었고 fetch가 걸러내지만,
   지어낸 만큼 수율이 깎인다. 계측값(`http_404` 비율)으로 추적 가능하다.
3. **라이브 연속 운영 미검증.** 크레딧 소진으로 라이브는 1일차만 돌았다. 충전 후
   `python tools/loop_runner.py --days 5 --count 6 --db data/loop.db`로 재개하면 된다.
   시뮬레이션이 로직은 보증하지만 **콘텐츠 품질의 날짜별 편차는 여기서만 드러난다.**
4. **비용 $1.14/일 (약 $34/월)**. 시뮬레이션에서 이틀에 한 번은 저수지로 처리되므로
   실질 비용은 더 낮을 수 있다. 더 줄이려면 `WEB_SEARCH_MAX_USES`를 6으로 낮추는 게
   첫 손잡이다(커버리지와 맞바꿈).
5. **시뮬레이터 수율은 라이브 1일 표본에 맞춘 값이다.** 계절성이나 주말 공급 감소는
   반영되어 있지 않다. 라이브 데이터가 쌓이면 `tools/sim_world.py` 상단 상수를 갱신해야 한다.

## 8. 재현 방법

```bash
# 라이브 (Anthropic 크레딧 소모)
python dry_run.py --count 6 --verbose --db data/tmp.db          # 1회 실행 + 단계별 통계
python dry_run.py --count 6 --mark-posted --db data/tmp.db      # 연속일 조건 재현
python tools/loop_runner.py --days 5 --count 6 --db data/loop.db

# 오프라인 시뮬레이션 (비용 $0)
python tools/loop_runner.py --simulate --days 7 --count 6 --quiet
python tools/loop_runner.py --simulate --legacy --days 7 --count 2 --quiet   # 변경 전 대조군
python tools/loop_runner.py --simulate --days 7 --count 6 --supply 2 --quiet # 공급 부족 조건

python -m pytest tests/test_zero_day_simulation.py -q           # 회귀 테스트
```

`loop_runner.py`는 매 회차 선정분을 게시 완료로 표시해 저수지를 실제로 소진시킨다.
이것이 프로덕션에서 0건이 나던 조건이다.
